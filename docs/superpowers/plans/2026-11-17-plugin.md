# story-engine plugin (Plan 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the story-engine Claude Code plugin locally (5 skills, 2 QA agents, 15 evals, manifests, README, SOURCES, LICENSE), install it from a local marketplace, and pass its evals. Nothing is published.

**Architecture:** Skills are Markdown `SKILL.md` files that load `knowledge/` entries on demand through route A (brief objective, then the domain's Goal map row, then `knowledge/index.md`, then only that ID's section). story-structure and story-draft end every output with a knowledge trace and run QA gates through two plugin agents. One stdlib Python check script guards the static structure; evals run `claude -p` against the working copy and are graded by a script, a grader agent and the user.

**Tech Stack:** Claude Code plugin format (`.claude-plugin/`, `skills/`, `agents/`), Markdown, Python 3 stdlib (no pytest installed; checks are plain `assert` scripts), `claude` CLI (`claude plugin validate`, `claude -p`, `claude plugin marketplace add`, `claude plugin install`), the skill-creator skill's eval viewer.

**Spec:** `docs/superpowers/specs/2026-11-17-plugin-design.md`, which extends `docs/superpowers/specs/2026-11-13-story-engine-design.md` (parent). Read both. Where they differ, the 2026-11-17 spec wins.

## Global Constraints

- Nothing is published: no `git push`, no remote, no public repo. Plan 3 does publication.
- `../destilado/` and `../md/` never enter this repo. Never modify `../destilado/fichas-gemini/` or `../md/`.
- Never edit files under `knowledge/` (they are the frozen output of Plan 1; IDs are append-only).
- Plugin name `story-engine`, version `0.1.0`, license MIT, LICENSE holder `sebdavila`.
- Skill content in English. Each skill `description` carries English, Spanish and Portuguese trigger phrases. The plugin answers in the user's language.
- Each `SKILL.md` stays under 500 lines.
- Skills reference knowledge as `../../knowledge/...` relative to the skill's base directory (unless Task 1 proves this fails; then `${CLAUDE_PLUGIN_ROOT}/knowledge/...` everywhere).
- Never name an ID that was not opened. Never read `knowledge/index.md` whole; search it with Grep for `| <ID> |`.
- knowledge-auditor: model `sonnet`, tools `Read, Grep, Glob`. story-reviewer: no `model` line (inherits), tools `Read`.
- Gate 2 passes when the auditor passes all 4 checks, the reviewer scores at least 14/20, and no rubric criterion scores 0. At most 2 fix rounds; anything still failing goes under a `## QA pending` section. "no QA" skips the gates; the trace is still written.
- Agent parallelism during evals: at most 3 Opus or 4 Sonnet runs at once.
- Commit messages in English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit on local `main` (no branch needed; nothing is pushed).
- Eval run outputs live in `../story-engine-workspace/` (outside the repo, never committed).

## Review Focus

1. **User writes in Spanish or Portuguese** → the answer is in that language; trace IDs and the trace labels stay as defined. Pinned by eval cases 1, 4, 6, 15 (assertion "answer language").
2. **No Goal map row fits the objective** → skill searches the Name column of `index.md`, keeps at most 2 candidates, and says so in the trace. Pinned by eval case 7 (Task 8).
3. **`index.md` read whole** (Read without offset/limit, about 12,000 words) → never happens. Pinned by `evals/check.py` flag `index_read_whole` asserted false on every case (Task 8).
4. **Plugin installed from a marketplace cache, not run from the repo** → knowledge paths still resolve. Pinned by Task 1 Step 4 and Task 10 Step 2.
5. **"no QA" said in another language ("sin QA")** → gates skipped, trace still present. Pinned by eval case 15 (Spanish).

## Shared contracts (used by several tasks)

**Brief** (kept in conversation, written as a block when story-coach builds it):
```
Brief
- Audience:
- Objective: <what they should think, feel, know or do>
- Domain: <one of the 10 domain file names>
- Goal map row: <exact Goal cell text, or "none: <keywords searched>">
- Format:
- Length:
- Material:
```

**Knowledge trace** (exact labels; ends every story-structure and story-draft output):
```
Knowledge trace
- Read: <files>
- Framework: <name> (<file> <ID>) -> where it is applied
- Techniques: <name> (<ID>) -> where it is applied
- Deviation: <why the framework differs from the Goal map row, or "none">
```

**Auditor verdict** (first lines of knowledge-auditor's reply):
```
Auditor verdict: PASS|FAIL
1. IDs exist: PASS|FAIL — <location>
2. Framework steps present: PASS|FAIL — <location>
3. Techniques placed: PASS|FAIL — <location>
4. Framework fits Goal map: PASS|FAIL — <location>
Ungrounded advice: <list or "none">
```
A missing trace is `Auditor verdict: FAIL` with check 1 `FAIL — no knowledge trace`.

**Reviewer verdict** (first lines of story-reviewer's reply):
```
Reviewer score: <n>/20
R01 <0-2> ... R10 <0-2>
Top problems:
1. <problem> — Fix: <fix>
2. ...
3. ...
```

**Invoking agents:** skills call the Agent tool with `subagent_type` `story-engine:knowledge-auditor` / `story-engine:story-reviewer`, and pass in the prompt the absolute path of the plugin's `knowledge/` directory (resolved from the skill's base directory) because agents have no base directory.
